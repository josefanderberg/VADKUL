## Analys

### Vad gick bra

**lat=0 sjönk från 26% → 16% — största förbättringen på en dag.**
Tre saker bidrog simultant: K2-geocoding-retry (stad-scan i adressfältet), K4 LLM (30 nya koordinater), och pre-save utländskt filter (279 event stoppades innan de sparades). Kombinationseffekten är tydlig — ingen enskild fix hade gett −10pp.

**category='other' halverades nästan — från 100% → 71%.**
Regelbaserad classifier (`classify.ts`) + K4-kategori täckte ~450 events. Starkast: music (113), social (80), education (55). Enkla mönster räcker långt för de vanligaste kategorierna.

**Pre-save utländskt filter fungerar bättre än väntat.**
279 event stoppades — fler än hela förra nattens nysparning (252). Bekräftar att stor andel av FB-scrapens råmaterial är icke-svenska event som läckte in via generiska sökord.

### Vad gick mindre bra

**K4 täcker bara 200 events — hårt tak skapar flaskhals.**
Om DB har 300+ lat=0-events nås en tredjedel aldrig. 164 av 200 missades på geocodning (82%), men kategorier fixades på 150 — så även geocode-missar bidrar med kategorivärde.

**Danska event sluppit igenom.**
`Bygglek lørdag`, `Åbent lørdag`, `Øver søndag` sparades trots danska titlar. `isForeignAddress` kontrollerar bara adressfältet — inte event-titeln. Titlar med `lørdag`, `søndag`, `åbent` bör fångas.

**Nominatim känner inte till lokala svenska venues.**
`Sveabiografen`, `Edsele Bygdegård`, `Bergnäsgården` — rimliga svenska platser som Nominatim saknar. Strukturellt problem; kräver en kompletterande källa (Google Maps API, OSM Overpass) för att lösa fullt ut.

**O'Learys AW-event i Gävle sparades 5 gånger.**
Samma event med identisk titel på 5 olika datum-URLs. Dedup sker på URL men URL:erna skiljer sig per datum. Behöver title+date-dedup för återkommande event.

**queries sjönk från 306 → 304** — teater-duplikat borttaget (korrekt), marginell effekt på resultat.
